# weekly-review — 周报

## 触发条件

- 每周固定复盘（默认周五或周日）
- 需要向他人汇报本周产出与风险
- 需要决定下周优先级

**不触发**：单日总结（写 daily-log 即可）；项目结项（走 `project-summary`）；纯数据查询（`kb.py stats`）。

## 输入

- 周期：周一 00:00 至周日 23:59（Asia/Shanghai）
- 七份 daily-log：`.dsh/knowledge/daily-logs/YYYY-MM-DD.md`
- 任务卡：`.dsh/tasks/{active,backlog,done/YYYY-MM}/`
- 本周新增 `dec-*`/`exp-*` 与 SOP 偏差记录

## 步骤

1. **定周期并列日志**：确定周一起止日期，逐一列出 7 个日志路径。
   **完成判据**：缺失的日期显式标「无日志」，不留空、不跳过。
2. **统计任务迁移**：`python .dsh/tools/kb.py search --type task --since <周一>`，并按卡状态核对新增/完成/阻塞/取消。
   **完成判据**：每类变更都能指到具体任务卡路径；数字与卡状态一致。
3. **统计新增决策与经验**：`python .dsh/tools/kb.py search --type decision --since <周一>`，经验同法（`--type experience`）。
   **完成判据**：列出 ID + 一句话结论；条数与 `kb.py stats` 的增量一致。
4. **核对 SOP 偏差**：对照本周 `sop-executor` 的偏差表与各 SOP 的 `last_updated`。
   **完成判据**：每条偏差有 SOP ID + 是否已回写版本；未回写的列入下周动作。
5. **算四个数字**：完成任务数、新增决策数、新增经验数、当前阻塞数。
   **完成判据**：四个数字都能从卡/条目数出来，不估算、不含跨周重复计数。
6. **写六段周报**：本周完成 / 进行中与风险 / 任务迁移 / 新增决策与经验 / SOP 偏差与改进 / 下周计划；每段 ≤5 行，问题带证据路径。
   **完成判据**：六段齐全；每条风险有影响与应对；下周计划 ≤3 项且各有验收判据。
7. **落盘并收口**：追加到本周周日 daily-log 的 `## 周报` 段；`python .dsh/tools/kb.py validate` → `index`。
   **完成判据**：文件存在且六段完整；validate 零 error；任务卡与看板已同步。

## 质量闸门

- [ ] 周期覆盖完整 7 天，缺失日志已标注
- [ ] 六段齐全且顺序固定
- [ ] 每个数字有来源（卡路径/条目 ID/命令输出）
- [ ] 风险段每条带影响与应对，不是罗列
- [ ] SOP 偏差有 SOP ID 与回写状态
- [ ] 下周计划 ≤3 项，各有验收判据
- [ ] 无「继续努力」「加强沟通」类空话
- [ ] `kb.py validate` 零 error

## 输出格式

```
周报：<周一> → <周日>
1. 本周完成：<≤5 条，带证据路径>
2. 进行中与风险：<任务 + 风险 + 应对>
3. 任务迁移：新增 n / 完成 n / 阻塞 n / 取消 n
4. 新增决策与经验：dec-…（一句结论）；exp-…（一句 prevention）
5. SOP 偏差与改进：<sop-id> 步骤 n 偏差 → 已回写/待回写
6. 下周计划：1) …（验收：…）
```

## 反面清单

- ❌ 把七篇日报拼起来当周报——周报要归纳与取舍，不是堆叠。
- ❌ 只写完成、不写风险——下周会重复踩同一个坑。
- ❌ 数字拍脑袋——每个数必须能追到卡或条目。
- ❌ 周报写完不更新任务卡与看板——下周启动时上下文是错的。
- ❌ 跨两周混算——周期边界固定，宁可漏算不可重算。

## 用例

**成功用例**：周五用户说「写周报」。扫 7 天日志（其中 1 天缺失已标注）；任务迁移新增 3 完成 2 阻塞 1；新增 2 条决策、3 条经验；1 条 SOP 偏差待回写；六段成文，下周计划 3 项各带验收；validate 零 error。

**边界用例**：用户周三说「先给我出个周报」。周期未结束 → 触发但降级为「周中快照」：只统计周一至当日，明确标注「非完整周期」，第 6 段改为「下半周计划」，不冒充完整周报。
