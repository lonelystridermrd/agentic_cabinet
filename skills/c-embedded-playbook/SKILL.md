# c-embedded-playbook — 模块设计与关键手法

> 本 Skill 只解决"**怎么设计**"，不解决"**写得合不合规**"（那是 `c-embedded-coding`）。
> 核心原则：**先有预算，再有方案；先有失败模式，再有正常路径。**

## 触发条件

- 新写一个模块/子系统（连接管理、缓存、表项、任务调度、配置同步）
- 在 socket 上做通信（TCP/UDP/Unix socket/多播）
- 选数据结构或内存分配策略（池 / arena / malloc / ring / hash / 树）
- 要做性能预算、优化，或回答"够不够快"
- 要决定线程模型、锁粒度、并发策略
- **不触发**：改一个函数内部实现（用 `c-embedded-coding`）；纯排障（用 `incident-responder`）

## 输入（六问，答不上就不设计）

1. **延迟**：P50 / P99 目标是多少？哪条路径是热路径？
2. **吞吐**：每秒多少事件/包/请求？峰值是均值的几倍？
3. **内存**：本模块预算多少 KB？单对象大小 × 数量上限？
4. **线程模型**：单线程事件循环 / 每连接一线程 / 线程池 / 多进程？谁调用本模块？
5. **失败模式**：内存耗尽、对端消失、超时、部分失败，各自怎么降级？
6. **可观测**：出问题时看什么？（计数器、日志、dump、指标）

> 六问里任何一项缺失，先向用户要数；**不要用"大概""应该够"代替数字**。

## 步骤

1. **收约束**：按上面六问记下数字；把用户没给的项标成"假设 + 待验证"，并在输出里显式列出。
2. **定主题**：按关键词路由到 reference——
   - socket / 连接 / 收发 / 分包 → `references/socket.md`
   - 内存 / 池 / ring / hash / 树 / 链表 / 布局 → `references/memory-and-structures.md`
   - 延迟 / 吞吐 / 优化 / 测量 → `references/performance.md`
   - 省内存还是省 CPU / 缓存值不值 / 批量还是逐条 → `references/tradeoff.md`
   - 线程 / 锁 / 原子 / 亲和 / 退出 → `references/concurrency.md`
3. **出 2 个以上方案**：每个方案写清数据结构、内存开销、延迟特征、失败模式、实现复杂度；给对比表，不直接给唯一答案（除非约束已把其它方案排除，此时写出"为什么排除"）。
4. **写骨架**：接口契约（函数 + 错误码 + 所有权）、核心结构体、不变量（invariants）、状态机。**不写全量实现**，先让用户确认形状。
5. **标假设**：把所有未验证的性能/容量假设列成"待测清单"，给出测量方法（perf 计数、打点、压测脚本）。
6. **落记录**：涉及选型 → `decision-logger`；涉及可复用套路 → `pattern-spotter`；实现阶段转 `c-embedded-coding`。

## 质量闸门

- [ ] 六个约束都有数字或显式标注"假设 + 待验证"
- [ ] 至少 2 个方案 + 对比表（内存 / 延迟 / 复杂度 / 失败模式 四列齐全）
- [ ] 核心结构体写出不变量（"任何时刻 `head <= tail`"这类可断言的条件）
- [ ] 每个失败模式都有降级动作（拒绝 / 丢弃 / 阻塞 / 重启）
- [ ] 没有"以后再优化"的空白项——要么现在给定预算，要么写进待测清单
- [ ] 方案没有照搬"大厂架构"（与当前约束不匹配的复杂度必须说明理由）

## 输出格式

```
约束：延迟 <x> / 吞吐 <y> / 内存 <z> / 线程模型 <m> / 失败模式 <f> / 可观测 <o>
方案对比：<表格，2–3 行>
推荐：<方案名> — <一句话理由>（不推荐项写出被排除的原因）
核心结构：<结构体 + 不变量>
失败路径：<每种失败的降级动作>
待测假设：<列表 + 测量方法>
下一步：<转 c-embedded-coding 实现 / 先做原型验证>
```

## 反面清单

- ❌ 没数字就开始设计（"高性能""低延迟"不是约束）
- ❌ 直接用 `malloc` + 链表解决一切（先问生命周期与数量上限）
- ❌ 单线程思路写多线程代码（共享状态、锁、可见性全没考虑）
- ❌ 为了"扩展性"引入三层抽象，实际只有两个调用点
- ❌ 把设计写成 500 行代码——骨架阶段只给形状
- ❌ 优化没有基线（改完凭感觉说"快多了"）

## 用例

**成功用例**：用户说"要做一个 2000 连接的 TCP 配置下发通道，延迟 P99 < 50ms，内存 < 20MB"。→ 六问补齐（吞吐、线程模型、失败模式）；路由到 `socket.md` + `concurrency.md`；给两方案：① epoll 单线程 + 每连接状态机（内存 ~4KB/连接，无锁）；② 4 线程 reactor + 无锁队列（吞吐高，复杂度高）；按 20MB/50ms 约束推荐 ①；写出不变量与背压策略；落 decision。

**边界用例**：用户说"这个函数里的 `memcpy` 能不能换成 `memmove`"。→ 不触发本 Skill（这是单点实现问题），直接用 `c-embedded-coding` 的 A14 回答：只在源/目的可能重叠时才需要 `memmove`，并给出重叠判定；不需要重新做设计评审。
