# 调研口径（个人要求，已确认）

> 这不是决策权重表，是**产出标准**。本 Skill 不做加权排序、不给最终推荐。
> 改这里 = 改调研的验收口径；变更需用户确认并追加记录。

## 一、调研姿态

- **客观搜集**，不做技术决策；决策由人。
- **先广度后深度**：广度阶段 ≥8 个候选，禁止一开始收敛。
- 深度阶段只做 **2–4 个方向**，避免精力摊薄。
- 淘汰项必须留在报告里，写明撞了哪条约束（避免后人重走）。

## 二、数据要求（硬性）

每个保留方案必须给**实测数据**，且数据来自**实际编译产物**：

| 指标 | 怎么取 |
|---|---|
| 产物体积 | `size` / `bloaty`，静态与动态分开，strip 与不 strip 分开 |
| 运行时内存 | 峰值 RSS（`/usr/bin/time -v`）或 heap 峰值（massif / `ru_maxrss`） |
| 启动时间 | `CLOCK_MONOTONIC` 打点，≥30 次取中位数与 P99 |
| 依赖数量 | `ldd` / `readelf -d` / 包管理器依赖树 |
| 编译时间 | `time make -j1`（单线程才可比） |

- 必须记录**可比性六要素**：架构、编译器与版本、编译选项、libc、内核、输入负载。
- 没有实测能力的项：标 `未实测`，写清原因与补齐成本，**不得**用他人数据冒充。

## 三、红线（已确认，一票否决）

- **无维护的项目**：停止维护 / 单人项目 / issue 长期无响应。
- **核心路径不能依赖外部服务**：常驻第三方服务、外部网络调用。

## 四、取舍倾向（作为条件映射的输入，不做加权打分）

- 核心路径：**性能优先**（先定预算，预算内即可）。
- 非核心路径：**交付速度优先**。
- 体积：嵌入式目标下体积是**约束**，不是可权衡的加分项。

## 五、输出形态

- 给方案、给选项、给数据、给**条件映射**。
- 不给"最终推荐"；允许给"若 X 则 A 更合适"。
- 每个结论可追到来源或实测记录。
