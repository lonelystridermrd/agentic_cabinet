# project-summary — 项目汇总

## 触发条件

- 项目/阶段结束，需要一次收口
- 要判断「目标是否达成」而不只是「做了多少」
- 需要把项目资产与经验交接给下一个项目

**不触发**：单周回顾（走 `weekly-review`）；单任务完成（更新任务卡即可）；还在进行中的项目（等边界清晰再做）。

## 输入

- 项目边界：起止日期、关联任务卡集合（active + done）
- 立项时的目标与验收判据（在任务卡 `## 目标` 或 `dec-*` 里）
- 决策条目：`python .dsh/tools/kb.py search --type decision --since <起始日>`
- 经验条目与产出物路径

## 步骤

1. **定边界与清单**：列出起止日期与全部关联任务卡 ID。
   **完成判据**：卡 ID 列表完整，状态为 `done`/`cancelled`/`in_progress` 的分开标注。
2. **目标 vs 交付**：逐条比对原目标与验收判据，标「达成 / 部分达成 / 未达成」，每条附证据路径。
   **完成判据**：目标条数 = 结论条数；无一条只有结论没有证据。
3. **还原决策链**：按时间排 `dec-*`，写「决策 → 影响的任务/交付」。
   **完成判据**：每个关键决策有后续影响；孤立决策标「未落地」并说明原因。
4. **提炼可迁移经验**：从 `exp-*` 中筛出 `prevention` 可跨项目复用的。
   **完成判据**：每条经验给「适用场景 + 不适用边界」；无边界的不算可迁移。
5. **清点产出资产**：代码/文档/Skill/Agent/SOP 清单，含路径与复用方式。
   **完成判据**：每个资产路径用 `read`/`glob` 验证存在；不存在的标「已废弃」。
6. **写改进建议**：3–5 条，每条对应一个已发生的问题 + 可执行动作 + 验收指标。
   **完成判据**：无「加强沟通」「提高意识」类建议；每条有验收方式。
7. **归档收口**：完成的卡移入 `done/YYYY-MM/`，同步 `TRACKING.md`，`python .dsh/tools/kb.py validate` → `index`。
   **完成判据**：validate 零 error；看板无孤儿卡；归档目录按完成月正确。

## 质量闸门

- [ ] 每条目标都有达成结论与证据
- [ ] 未达成项写明差距与原因，不淡化
- [ ] 决策链无断点，孤立决策已标注
- [ ] 可迁移经验有适用边界
- [ ] 产出资产路径均已验证存在
- [ ] 改进建议可执行、可验收
- [ ] 归档与看板同步完成
- [ ] `kb.py validate` 零 error

## 输出格式

```
项目：<名称> · <起> → <止> · 任务 <n> 张（done x / cancelled y）
目标 vs 交付：
| 目标 | 结论 | 证据 |
决策链：dec-… → <影响>；孤立：<列出>
可迁移经验：exp-…（适用…；不适用…）
产出资产：
| 类型 | 路径 | 复用方式 |
改进建议：1) <问题> → <动作> → <验收指标>
```

## 反面清单

- ❌ 只列成果不提未达成——总结失去判断价值。
- ❌ 决策链只堆 ID 不说影响——无法看出哪个决策真正起作用。
- ❌ 经验写成「要注意 XX」——没有适用边界的经验不可迁移。
- ❌ 资产路径不核实——交接时才发现文件不存在。
- ❌ 改进建议没有验收指标——下个项目还会重复同样的问题。

## 用例

**成功用例**：以阶段 0 收口为例：关联任务卡全部关闭且 done/cancelled 分明；目标逐条比对，未达成项附验证输出；决策链 G1–G7 落到具体文件；可迁移经验各带适用边界；资产清单逐个验证路径存在；归档后 validate 零 error。

**边界用例**：项目进行到一半用户说「先总结一下」。目标尚未可判定 → 触发但降级为「中期快照」：只写已完成部分与当前风险，明确标「目标达成度暂不可评」，不输出结项结论。
