# 技术选型调研 SOP

## 适用与不适用

- 适用：有真实备选、有可判定评估维度的选型。
- 不适用：只有一个可行方案（直接记录后果，不走调研）、纯学习性阅读。

## 步骤

1. **查历史** — 自己
   - `python .dsh/tools/kb.py search <关键词> --type decision`
   - 完成判据：命中则先判「结论是否仍成立」，成立即复用、不重开调研
2. **拆子问题** — `research-assistant`
   - 每个子问题对应一个评估维度（成本/复杂度/可回退性/生态/合规）
   - 完成判据：维度由用户确认，≤5 个
3. **多源取证** — `tech-investigator`（派发）
   - 官方文档 + 社区讨论 + 必要时论文；每条事实标注来源
   - 完成判据：每个维度至少 1 条可追溯来源
4. **构建对比矩阵** — `comparison-maker`（派发）
   - 完成判据：每格填「可判定事实」，不写"好/不好"
5. **给推荐 + 标注不确定性** — 自己
   - 完成判据：明写「什么新信息会推翻结论」
6. **落决策** — `decision-logger`
   - 完成判据：`dec-*` 入库，`confidence` 与正文理由一致

## 检查点

- [ ] 已查历史决策，无重复调研
- [ ] 评估维度经用户确认
- [ ] 每条事实有来源，推测标 `推断`
- [ ] 矩阵无主观形容词
- [ ] 决策条目已落库且 status 明确（proposed/accepted）
