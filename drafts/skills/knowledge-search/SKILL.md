# knowledge-search — 历史查证

## 触发条件

- 需要判断「这个问题库里有没有先例」
- 需要为一件事找可引用的 `dec-*` / `exp-*` / `sop-*`
- 多个 Skill 的「查历史」步骤需要统一口径（decision-logger / research-assistant / sop-executor / bootstrap 都在用）

**不触发**：已知条目 ID 直接读文件；纯计数（`kb.py stats`）。

## 输入

- 一句问题描述
- 可选的限定：类型（decision/experience/sop/task）、domain、时间下限

## 步骤

1. **拆词**：从问题里提取 3–5 个检索词，覆盖三类词：
   - 领域词（`auth` / `typescript` / `索引`）
   - 症状词（`401` / `编码` / `漏召回`）
   - 决策词（`选型` / `方案` / `替代`）
2. **多词检索**：每个词跑一次 `python .dsh/tools/kb.py search <词> --limit 10`；同义/近义词换一轮（中文 ↔ 英文，如「索引/index」）。
3. **判命中类型**：统计命中的类型数。三类齐全 → 有完整先例；只有一类 → 部分先例（说明缺哪类）。
4. **读关键条目**：只读命中的前 2–3 条正文，确认「结论是否仍成立」（看 `status` 与 `supersedes`）。
5. **给结论**：分三档——
   - `有直接先例`：引 ID + 一句话结论 + 是否仍有效
   - `有相关但非同一问题`：引 ID + 差异点
   - `无先例`：写清「试过哪些词、扫了哪些类型仍无命中」，避免下次重复查
6. **回执**：引用优先，其次才是自己的推理；不允许在「无先例」时假装有先例。

## 质量闸门

- [ ] 至少 3 个检索词，且包含中文与英文各一组（若有对应译名）
- [ ] 引用的 ID 真实存在（打开过文件，不是只看到标题）
- [ ] 明确区分「直接先例 / 相关 / 无先例」三档
- [ ] 无先例时写清已试过的词与范围
- [ ] 不把「相关」说成「就是同一个」

## 输出格式

```
结论：有直接先例 | 有相关但非同一问题 | 无先例
检索词：<a> / <b> / <c>（各命中 n 条）
引用
- dec-…（结论一句；status: accepted；是否仍有效：是）
- exp-…（prevention 一句）
差异/缺口：…
建议：<直接用 | 走 decision-logger 新建 | 无需处理>
```

## 反面清单

- ❌ 只搜一个词就断言"没有先例"
- ❌ 看到标题相似就引用，不读正文
- ❌ 引用已 `superseded` 的条目当作现行结论
- ❌ 把检索结果整段贴给用户（只需 ID + 一句话 + 差异）
