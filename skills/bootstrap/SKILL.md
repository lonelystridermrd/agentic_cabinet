# bootstrap — 日常编排

## 触发条件

- 会话开工（用户说「开始」「今天做什么」「继续上次」）
- 收到复合需求，需决定拆解与执行者
- 执行中需要切换 Skill / 派子 Agent

**不触发**：单步问答、纯检索（直接用 `kb.py search`）、纯记录（直接用 decision-logger / experience-capture）。

## 启动规程（开工四件事）

1. 读当日 daily-log：`.dsh/knowledge/daily-logs/YYYY-MM-DD.md`，没有就用骨架新建。
2. 扫 `.dsh/tasks/active/`：列出 `in_progress` 与 `blocked`，标出「今天必须推进」的 ≤3 项。
3. 按任务 tag 检索历史：`python .dsh/tools/kb.py search <关键词> --limit 5`。
   **必须主动引用命中的 `dec-*`/`exp-*`**，并说明「为什么相关」——引不出就说明白「库里没有先例」。
4. 给优先级：每项一句话验收判据；判据写不出来的不进今天。

## 步骤

1. **定形态**：任务 → 判定由谁执行（自己 / Skill / 子 Agent / Tool）。判据见 `make-skill` 的形态判定树。
2. **出计划**：≥3 步先给计划表（步骤 / 执行者 / 产出 / 验收），等用户确认；用户已明确授权时展示后立即执行。
3. **派发**：走 `agent-dispatch` 六段 prompt（角色/任务/输入/权限/知识库/输出）；只读卡片写死「不得写文件」。
4. **收口**：每步完成即更新任务卡 `subtasks` 与 daily-log，不攒到最后。
5. **捕获检查**（每次收口必做三问）：
   - 有新决策？→ `decision-logger`
   - 有新坑（>10 分钟）？→ `experience-capture`
   - 有重复步骤（≥3 次）？→ 标「可 SOP 化」，交 `make-skill` / `sop-executor`
6. **次日验证**：把当日 `dec-*`/`exp-*` 写进 daily-log 的「明日召回」段，次日启动规程第 3 步会命中。

## 权限与白名单（硬约束）

| 执行者 | 可写范围 |
|---|---|
| bootstrap 自身 | `.dsh/**`（知识库、任务、Skill、Agent 卡片） |
| 只读子 Agent | 无（prompt 内写死「不得写文件」） |
| 读写子 Agent | 仅卡片 `can_write` 声明的 `.dsh/` 内路径 |
| 业务文件 | **默认禁止**；需用户点名授权，且一次只授权一个路径范围 |

禁止：删除、`git push`、改 CI/部署配置、写 `.dsh/` 之外的任何文件（未授权时）。

## 质量闸门

- [ ] 计划在动手前展示（复合任务）
- [ ] 每步都指定了执行者与验收判据
- [ ] 引用了 ≥1 条历史决策/经验，或明确说明无先例
- [ ] 收口时三问都回答过（决策/经验/可 SOP 化）
- [ ] 任务卡与 daily-log 已更新
- [ ] 0 次越权写文件

## 输出格式

```
计划（<n> 步）
| # | 步骤 | 执行者 | 产出 | 验收 |
|---|------|--------|------|------|

上下文：dec-xxx（因为…）/ exp-yyy（因为…）/ 无先例

执行摘要
- 完成：…
- 阻塞：…（原因 + 需要谁）
- 新捕获：dec-… / exp-…
- 明日召回：…
```

## 反面清单

- ❌ 一边执行一边改计划（改了要先说）
- ❌ 把子 Agent 原文整段转贴回主会话
- ❌ 越权写业务文件（最常见失控点）
- ❌ 收口只写「已完成」，不写验收证据
- ❌ 同一个任务当天派发两次（先查 `agent-calls/<date>.jsonl`）

## 用例

**成功用例**：用户说「把这个模块重构一下」。bootstrap 先检索 `dec-*`（命中 auth 相关决策则引用），出计划：spec-writer 澄清范围 → refactor-planner 出方案 → 用户确认 → 实现 → code-reviewer 审 → experience-capture 记录。每步验收可判定，写操作仅限 `.dsh/`。

**边界用例**：用户说「顺手把 config.yml 的端口改一下」。这是单步、要写业务文件 → 不走编排：直接说明「需要你授权写该文件」，拿到点名的路径后再改，且改完给出 diff 证据。
