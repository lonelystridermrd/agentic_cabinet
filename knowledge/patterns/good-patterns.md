# 好模式库

> 由 `pattern-spotter` 维护。每条 = 模式名 + 适用场景 + 最小做法 + 已验证来源。

## good-frontmatter-first

- **适用**：任何要长期复用的结构化资产（决策/经验/SOP/任务）。
- **做法**：先定 schema 与枚举，再写正文；正文只放「为什么」，枚举字段放「是什么」。
- **好处**：可脚本校验、可索引、可跨条目比对；字段变更能靠迁移脚本批量处理。
- **来源**：`.dsh/schemas/*.json`、dec-2026-11-07-g4-confidence-scale。

## good-checkbox-gate

- **适用**：Skill 的质量闸门、SOP 的检查点、任务卡验收。
- **做法**：每项写成 `- [ ] 可判定语句`，判定标准必须是「看一眼就能答 yes/no」。
- **好处**：把「做完没做完」的争论变成勾选；复盘时能定位是哪一关失守。
- **来源**：全部 Skill 的 `## 质量闸门`。

## good-sandbox-then-promote

- **适用**：任何自动生成物进入正式资产库之前。
- **做法**：生成物落 `.dsh/drafts/`，人工一次确认，再由 `kb.py promote` 迁入正式目录。
- **好处**：治理成本压到一次 yes/no，同时保留草稿可审计。
- **来源**：dec-2026-11-07-g3-draft-promote-gate。

## good-capture-then-recall

- **适用**：验证知识库是否真的在起作用。
- **做法**：当天捕获的 `dec-*`/`exp-*` 写进 daily-log 的「明日召回」；次日启动规程主动检索并引用。
- **好处**：形成「记录 → 次日被引用」的闭环证据，而不是只堆条目。
- **来源**：`.dsh/skills/bootstrap/SKILL.md` 启动规程第 3 步。
