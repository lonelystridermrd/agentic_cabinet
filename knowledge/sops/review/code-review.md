# 代码审查 SOP

## 适用与不适用

- 适用：有明确变更面（diff 或文件清单）的代码改动。
- 不适用：需求评审（`spec-writer`）、架构评审（`architect`）。

## 步骤

1. **定范围** — 自己
   - `git diff --stat`，或用用户给定的文件清单
   - 完成判据：范围行数已知，超出 400 行则分批
2. **派发审查** — `agent-dispatch` → `code-reviewer`
   - prompt 必须写死：只读、不得修改文件、只审变更面
   - 完成判据：拿到分级问题清单（P0–P3）
3. **复核抽样** — 自己
   - 抽 2 条结论回原文核对，防幻觉
   - 完成判据：抽样一致，或已剔除不一致项
4. **定结论** — 自己
   - 可合并 / 需修改 / 需重做 + 最大单点风险
   - 完成判据：P0 全部有明确处置
5. **记录** — `experience-capture`
   - 只记录「非显然的缺陷模式」；同一模式复发 → 追加到旧条目
   - 完成判据：新增或复发记录已落库

## 检查点

- [ ] 审查范围明确（diff/文件清单）
- [ ] 每条问题有 `文件:行` 与证据片段
- [ ] 抽样复核 ≥2 条
- [ ] P0 全部有处置，无「待定」
- [ ] 秘钥/凭据类问题按 P0 处理且未复制原文
