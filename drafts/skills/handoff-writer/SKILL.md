# handoff-writer — 会话交接摘要

## 触发条件

- 一次会话产生跨会话的未完成工作（任务卡状态非 `done`）
- 用户明确收工/交接
- 上下文即将结束但还有 `in_progress` 项

**不触发**：单步问答、任务已 `done` 且无后续。

## 输入

- 当前任务卡（`.dsh/tasks/active/`）
- 本次会话新增的 `dec-*` / `exp-*`
- 未决问题与阻塞项

## 步骤

1. **取状态**：读 active 任务卡的 `subtasks` 与「下一步」；`python .dsh/tools/kb.py search <任务关键词> --since <今天>` 取本次新增条目。
2. **写四段**：已完成 / 决定 / 未决 / 下次第一步。每段 ≤5 条，只留「下次必须知道」的。
3. **落到 daily-log**：追加 `## 交接（HH:MM）` 段到 `.dsh/knowledge/daily-logs/YYYY-MM-DD.md`。
4. **校验**：确认「下次第一步」是一个可立即执行的动作（有路径/有命令），不是"继续推进"。
5. **回执**：给出摘要 + 下次第一步 + 需要用户确认的未决项。

## 交接模板

```markdown
## 交接（HH:MM）
### 已完成
- 
### 决定（引用 ID）
- dec-… 
### 未决（需要谁）
- 
### 下次第一步（可立即执行）
- `python .dsh/tools/kb.py search …` / 编辑 `<路径>`
```

## 质量闸门

- [ ] 「下次第一步」是可执行动作，含具体路径或命令
- [ ] 未决项写清「等谁 / 等什么」
- [ ] 决策只引 ID，不复述全文
- [ ] 已追加到当日 daily-log

## 输出格式

```
已写入 daily-log：## 交接（HH:MM）
下次第一步：<动作 + 路径/命令>
未决：<n> 项（等 <谁>）
```

## 反面清单

- ❌ 把整段会话复述一遍（交接不是 transcript）
- ❌ 「下次继续优化」——不可执行
- ❌ 只写在聊天里不落盘 —— 下次会话读不到
