# L2 · 迭代修改检查（diff 范围 + 影响面）

> 触发：修改已有文件。目标不是"重查一遍全部"，而是"改动点和它波及的地方都查到"。

## 1. 范围

- 只对 `git diff --name-only` 里的文件跑 `style_check.py`。
- 新增文件按 L0 全量检查。
- 格式改动与逻辑改动分开提交；混在一起时先拆。

## 2. 影响面（按改动类型）

| 改动 | 必须检查 |
|---|---|
| 函数签名 | 所有调用方；头注释同步；错误码是否变 |
| 结构体字段 | 所有初始化点、`sizeof` 用法、序列化兼容 |
| 错误码 | 调用方分支是否覆盖新码；文档同步 |
| 全局/静态变量 | 线程安全、重入、初始化顺序 |
| 公开头文件 | 所有 include 方能否编过；ABI 是否破坏 |
| 定时器/线程逻辑 | 退出路径、join 时机、锁序 |

## 3. 迭代专用检查项

- [ ] 改动文件都跑过 style_check，且集合 == diff 集合
- [ ] 新增分支有对应测试或明确标注"未覆盖原因"
- [ ] 没有顺手改无关代码（范围蔓延）
- [ ] 旧行为兼容性：调用方未改也能编过
- [ ] 若改了公开接口，`README`/Doxygen 同步

## 4. 与 L1 的关系

- L1（30 项完整清单）在**提交前**跑一次，覆盖全部改动文件。
- L2 是 L1 的子集 + 影响面分析，可在每次编辑后快速跑。
- 二者冲突时以 L1 为准。
