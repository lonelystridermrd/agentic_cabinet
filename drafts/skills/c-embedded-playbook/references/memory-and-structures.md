# 内存与数据结构（选型 + 手法）

> 先回答两个问题：**这块内存活多久？**（生命周期）**最多有多少个？**（数量上限）
> 答不上来 → 不要选分配器，先补需求。

## 1. 分配策略选型

| 策略 | 分配延迟 | 碎片 | 上限可控 | 适用 |
|---|---|---|---|---|
| 全局/静态数组 | 0 | 无 | 是 | 数量固定、启动即定（表项、连接槽） |
| 栈 | 极低 | 无 | 线程栈大小 | 小对象、短生命周期（<4KB） |
| 固定块池（free list） | O(1) | 无 | 是 | 同尺寸对象、热路径（报文缓冲、会话对象） |
| Slab / 多尺寸池 | O(1) | 低 | 是 | 几种固定尺寸混合 |
| Arena / 一次性分配 | O(1) | 无（整块释放） | 是 | 请求级临时对象（解析期） |
| `malloc` | 微秒级、不可预测 | 有 | 否 | 启动期、低频配置路径 |

**默认**：热路径（每包/每事件）禁止 `malloc`；数量有上限的对象一律预分配池。

## 2. 池的实现要点

```c
struct blk { struct blk *next; };          /* 空闲块自身存 next，零额外开销 */
struct pool { struct blk *free; size_t blk_size; uint32_t total, used; };
```

- 块大小按 cache line 对齐（64B）取整，避免跨 cache line。
- 耗尽策略必须选定：返回 NULL（调用方丢弃/拒绝）或阻塞等待（有超时）。
- 线程安全：每线程一个池（无锁，最推荐）> 全局池 + 锁 > 无锁栈（ABA 风险，需 tag）。
- 池对象**不清零**是性能特性；复用时显式初始化必要字段，别假设全零。
- 池要能报统计：总量、已用、峰值、分配失败次数——否则线上无法判断是否该扩容。

## 3. 所有权模型（必须写进头注释）

| 模型 | 写法 | 释放责任 |
|---|---|---|
| 调用方拥有 | `foo(const char *name)` 借用 | 调用方 |
| 被调方接管 | `foo(char *name)` 注释"takes ownership" | 被调方 |
| 返回新对象 | `struct x *x_new(void)` | 调用方 `x_free` |
| 借用出参 | `int x_get(struct x **out)` | 仍归原主，禁止 `free` |

- 一个模块只允许一种 `x_new/x_free` 配对命名；禁止混用 `create/destroy/destroy_x/release`。
- 结构体里含指针时，必须提供 `_clone` 或明确"禁止浅拷贝"（注释 + 必要时用不透明类型）。

## 4. Ring buffer（环形队列）

- 单生产者单消费者（SPSC）：`head`/`tail` 用 `_Atomic size_t`，配合 `memory_order_acquire/release`，可完全无锁。
- 多生产者：要么加锁，要么用 CAS 循环（注意 ABA 与长度计算）。
- 容量取 2 的幂，用 `& (cap - 1)` 代替取模。
- 满/空判定：留一个空位法（`tail + 1 == head` 为满）或独立计数（更直观，需原子）。
- 覆盖策略：满时丢弃新数据（保旧）还是覆盖旧数据（保新）——按业务定，写进名字（`_ring_drop_new` / `_ring_overwrite`）。
- 批量入队/出队接口（`push_n/pop_n`）比逐条快，尤其配合 `writev`/`sendmmsg`。

## 5. 哈希表

| 项 | 建议 |
|---|---|
| 冲突处理 | 链地址（删除简单、可容忍高负载）/ 开放寻址（缓存友好、负载因子敏感） |
| 负载因子 | 链地址 ≤1.0；开放寻址 ≤0.7，超了扩容 |
| 哈希函数 | FNV-1a 或 xxHash；不要用"首字母 + 长度" |
| 扩容 | 成倍扩容 + 全量 rehash（有停顿）；延迟 rehash 适合大表 |
| 删除 | 开放寻址用墓碑标记；链地址直接摘链 |
| 迭代安全 | 明确"迭代期间能否删除"；不能就返回快照或用 `safe` 迭代器 |

- 键的比较成本要算进去：字符串键先比哈希再比内容，长度前缀可加速。
- 表项内存布局：把 key 存在表内（inline）比"指针指向外部"少一次访存。

## 6. 树 / 有序结构

| 结构 | 插入 | 查找 | 适用 |
|---|---|---|---|
| 有序数组 + 二分 | O(n) 搬移 | O(log n) | 读多写少、数量小（<1k） |
| 红黑树 | O(log n) | O(log n) | 频繁增删、需要有序遍历 |
| 跳表 | O(log n) 期望 | O(log n) | 需要并发、实现比红黑树简单 |
| 基数树 / Trie | O(k) | O(k) | 前缀匹配（IP 路由、字符串前缀） |
| 最小堆 | O(log n) | O(1) 取最小 | 定时器、超时管理 |

- 嵌入式优先"有序数组 + 二分"：无指针、cache 友好、可静态分配。
- 树的节点分配：预分配节点池，别每个节点一次 `malloc`。

## 7. 内存布局与 cache

- AoS vs SoA：遍历全部字段 → AoS；只遍历少数字段 → SoA（cache 利用率高）。
- 热字段与冷字段分离：把每事件都访问的字段放结构体前部，避免跨 cache line。
- 伪共享：多线程各自写的计数器用 `char pad[64]` 隔离，或用 per-thread 计数 + 汇总。
- 结构体大小关注：`sizeof` 打印确认，别假设编译器没加 padding；必要时调整字段顺序（大字段在前）。
- `__attribute__((packed))` 只用于线上格式；本地结构体不要 packed（非对齐访问慢且可能异常）。

## 8. 内存错误检测

- 开发/CI：`-fsanitize=address,undefined`；`valgrind --leak-check=full`。
- 运行期自检（可选）：分配计数（`alloc_cnt - free_cnt`）、池水位、每模块内存统计。
- 越界检测：在调试构建里给缓冲加 guard（前后魔数），释放时校验。
- 泄漏定位：ASan 的 `LSAN` + 启动/停止快照对比。
