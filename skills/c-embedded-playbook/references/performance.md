# 性能预规划与优化

> 原则：**先预算，再测量，最后优化。** 没有测量的"优化"是赌博，没有预算的"性能"是空话。

## 1. 先定预算（写进设计文档）

| 指标 | 写法 | 例 |
|---|---|---|
| 延迟 | P50 / P99 / 最大值 | P99 < 50ms，最大 < 200ms |
| 吞吐 | 每秒事件数 / 字节数 | 2000 连接 × 100 msg/s |
| CPU | 核数配额 / 单核占用 | ≤ 1 核的 30% |
| 内存 | 常驻 + 峰值 | 常驻 < 20MB，峰值 < 30MB |
| 启动时间 | 从进程启动到可服务 | < 2s |

预算要能拆到路径：**每条热路径分到多少微秒**。拆不出来说明架构还没想清。

## 2. 建立基线（没有基线不许优化）

- 计数：`perf stat -e cycles,instructions,cache-misses,context-switches`。
- 打点：`clock_gettime(CLOCK_MONOTONIC)` 取差值，累计 min/avg/P99（用直方图，别只存均值）。
- 追踪：`perf record -g`、`ftrace`、`bpftrace`（内核 ≥4.9）、`strace -c`（syscall 次数）。
- 压测：固定输入、固定核数、固定并发；记录硬件与内核版本。
- 基线要**入库**（脚本 + 结果），否则下次无法比较。

## 3. 定位顺序（从便宜到贵）

1. **算法复杂度**：O(n²) 改 O(n log n)，收益通常最大。
2. **数据结构**：链表遍历改哈希/数组；减少指针追逐。
3. **syscall 次数**：每包一次 `send` → `sendmmsg`/`writev` 批量；`stat`/`open` 缓存。
4. **拷贝次数**：用户态 ↔ 内核态拷贝、`memcpy` 链；零拷贝（`sendfile`/`splice`）适用条件是"数据不需要在用户态修改"。
5. **缓存局部性**：AoS→SoA、热冷分离、预取。
6. **锁竞争**：per-thread 计数、分片锁、无锁队列。
7. **指令级**：分支预测（likely/unlikely）、内联、SIMD——最后做，收益通常 <5%。

## 4. 常见手段与适用条件

| 手段 | 收益 | 代价 / 前提 |
|---|---|---|
| 批量 IO（`sendmmsg`/`recvmmsg`/`writev`） | syscall 减少 5–10× | 需要能攒批；增加延迟 |
| 零拷贝（`sendfile`/`splice`） | 省一次拷贝 | 数据不能改；fd 类型受限 |
| 内存池 | 分配延迟 O(1) | 需要上限；可能浪费 |
| 查表代替计算（CRC、LPM） | 快 3–10× | 表占内存；cache 压力 |
| 预计算/缓存 | 免重复计算 | 失效逻辑复杂 |
| 无锁队列 | 免锁等待 | 实现难；只适合 SPSC/MPSC 特定形态 |
| CPU 亲和 + 隔离 | 减少迁移与抖动 | 核数要求；影响其它进程 |
| 惰性计算 | 省掉不用的工作 | 首次访问变慢 |

## 5. 何时停止

- 达到预算即停；继续优化必须有**新的预算目标**。
- 优化让代码复杂度显著上升（可读性、可测性下降）→ 必须记 `dec-*`，写清收益数字与代价。
- 优化只对特定输入有效（分支预测/缓存友好）→ 要在最坏输入下也验证。

## 6. 回归与门限

- 基准脚本与数据入库；CI 跑固定场景，超过基线 ±5% 报警。
- 每次性能相关改动附"改前/改后"两组数字，同一台机器、同一份输入。
- 记录环境：CPU 型号、核数、内核版本、编译选项（`-O2` vs `-O3` 差异可能很大）。

## 7. 反模式

- ❌ 先优化再测量（"我觉得这里慢"）。
- ❌ 微基准代替真实负载（cache 全热、无锁竞争、无 IO）。
- ❌ 用 `sleep` 做同步或限速（精度差、掩盖竞态）。
- ❌ 只看均值不看 P99（均值 1ms、P99 500ms 的系统对用户就是卡的）。
- ❌ 优化了 5% 却引入 3 个 bug 和 200 行复杂度。
- ❌ 把"减少日志"当性能优化（先确认日志真的是瓶颈，通常不是）。
