# 命名规范 v1.0

> 适用范围：`.dsh/` 下全部知识条目、任务卡、Skill、子 Agent 与索引产物。
> 闸门决策：G1（经验库分类维度）已按「领域主 tag + 问题类型副 tag」定稿，见 `.dsh/knowledge/decisions/2026-11-07-g1-experience-taxonomy.md`。

## 1. ID 规则

ID = `<前缀>-<日期>-<slug>`（SOP 例外，见下）。日期一律 `YYYY-MM-DD`（本地时区 Asia/Shanghai）。

| 对象 | 前缀 | 形态 | 示例 |
|---|---|---|---|
| 决策 | `dec` | `dec-YYYY-MM-DD-<slug>` | `dec-2026-11-07-g1-experience-taxonomy` |
| 经验 | `exp` | `exp-YYYY-MM-DD-<slug>` | `exp-2026-11-07-ps-gbk-python-stdout` |
| SOP | `sop` | `sop-<domain>-<slug>` | `sop-coding-feature-development` |
| 任务卡 | `TASK` | `TASK-YYYY-MM-DD-<slug>` | `TASK-2026-11-07-auth-refactor` |
| 模式 | `pat` | `pat-<good\|anti\|recurring>-<slug>` | `pat-anti-manual-index` |
| Skill | — | kebab-case，与目录名一致 | `decision-logger` |
| 子 Agent | — | kebab-case，与卡片文件名一致 | `code-reviewer` |

## 2. slug 规则

- 只允许小写字母、数字、连字符；正则：`^[a-z0-9]+(-[a-z0-9]+)*$`。
- 2–6 个词，能独立读懂，不写无信息词（`misc`、`tmp`、`test1`、`new`）。
- 英文优先；专有名词保留原形（`jwt`、`oauth2`、`typescript`）。
- Skill 名必须匹配 DSH 装载器约束 `^[a-z0-9]+(-[a-z0-9]+)*$`，否则整条 Skill 被静默跳过。

## 3. 文件名规则

| 对象 | 路径 | 说明 |
|---|---|---|
| 决策 | `.dsh/knowledge/decisions/<id>.md` | 文件名 = ID |
| 经验 | `.dsh/knowledge/experiences/<domain>/<id>.md` | `<domain>` ∈ `coding` `debugging` `architecture` `process` |
| SOP | `.dsh/knowledge/sops/<domain>/<slug>.md` | 文件名 = ID 去掉 `sop-<domain>-` 前缀 |
| 任务 | `.dsh/tasks/{active,backlog,done/YYYY-MM}/<id>.md` | 归档目录按完成月 |
| 日志 | `.dsh/knowledge/daily-logs/YYYY-MM-DD.md` | 一天一个文件 |
| 调用日志 | `.dsh/knowledge/agent-calls/YYYY-MM-DD.jsonl` | 一行一次派发 |
| Skill | `.dsh/skills/<name>/SKILL.md` | 目录 bundle，可选 `references/` `scripts/` `assets/` |
| 子 Agent | `.dsh/agents/<name>.md` | 平铺 persona 卡片 |

## 4. front-matter 强制字段

所有知识条目以 `---` 开头，字段顺序固定（便于人眼与脚本共同解析）：

- 决策：`id` `date` `context` `decision` `alternatives` `rationale` `consequences` `confidence` `tags` `status`
- 经验：`id` `date` `category` `domain` `problem_type` `trigger` `symptom` `root_cause` `fix` `prevention` `tags` `confidence`
- SOP：`id` `domain` `name` `version` `last_updated` `trigger` `estimated_time`
- 任务：`id` `title` `status` `priority` `created` `updated` `domain` `related_decisions` `related_experiences` `subtasks`

枚举值（脚本校验，非枚举即失败）：

- `confidence`：`high` | `medium` | `low`（G4 定稿，附一句理由写进正文 `## 置信度理由`）
- `status`（决策）：`proposed` | `accepted` | `rejected` | `superseded` | `deprecated`
- `status`（任务）：`backlog` | `in_progress` | `blocked` | `done` | `cancelled`
- `priority`：`P0` | `P1` | `P2` | `P3`
- `domain`（经验）：`coding` | `debugging` | `architecture` | `process`
- `problem_type`：`bug` | `performance` | `tooling` | `process` | `knowledge`

## 5. tag 规则

- 全小写 kebab-case，单数优先（`auth` 不写 `auths`）。
- 每类条目 2–6 个 tag；第一个 tag 默认等于 `domain`（经验）或主领域（决策）。
- 复用优先：写 tag 前先跑 `.dsh/tools/kb.py tags`，已有 tag 不新造同义词。

## 6. 唯一性与冲突

- ID 全库唯一；同主题再次决策不覆盖旧条目，新条目在 `supersedes` 字段指向旧 ID，旧条目 `status: superseded`。
- 同一 slug 同日重复 → 序号后缀 `-2`、`-3`，不覆盖。

## 7. 空目录与占位

每个 leaf 目录放 `.gitkeep`；每类目录放一段 `README.md` 说明「放什么 / 不放什么 / 由哪个 Skill 写入」。
